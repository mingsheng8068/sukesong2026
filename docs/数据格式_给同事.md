# 合成补充数据和知识文档：格式约定

> 给 PdM 同事。代码按下面的表头读取，**表头和取值请照抄**，有疑问先问再填。官方数据（设备台账、传感器、故障维修单、生产工单）不用动，这里只补官方没有的部分。

## 通用约定

- CSV 用 UTF-8 编码，第一行是表头，逗号分隔；单元格里不要有英文逗号（需要时用中文逗号“，”）。
- 时间统一写 `YYYY-MM-DD HH:MM`，日期写 `YYYY-MM-DD`。
- 设备编号、设备名称、部件名必须和官方台账**一字不差**：

| 设备编号 | 设备名称 | 产线 | 维保周期（天） | 关键部件 |
|---|---|---|---|---|
| EQ-CNC-001 | 五轴加工中心 | L01 | 90 | 主轴 / 丝杠 |
| EQ-CNC-002 | 五轴加工中心 | L02 | 90 | 主轴 / 丝杠 |
| EQ-IM-011 | 注塑机 | L03 | 60 | 螺杆 / 加热圈 |
| EQ-IM-012 | 注塑机 | L04 | 60 | 螺杆 / 加热圈 |
| EQ-RB-021 | 装配机器人 | L05 | 120 | RV减速机 / 伺服 |
| EQ-RB-022 | 装配机器人 | L06 | 120 | RV减速机 / 伺服 |
| EQ-AGV-031 | AGV搬运车 | L07 | 180 | 电池 / 驱动轮 |
| EQ-OVN-041 | 回流焊炉 | L08 | 90 | 发热管 / 风机 |

- 每行最后一列 `source` 固定写“合成”。全部内容都是自编的，不要用公司的数据、设备编号和文档。

## 1. 维保记录 `data/synthetic/maintenance.csv`

每台设备覆盖 2026-03 到 2026-09，按上表的维保周期排。

```csv
record_id,equipment_id,component,maint_type,start_time,end_time,content,result,next_planned_date,source
MT-RB022-0420,EQ-RB-022,RV减速机,计划保养,2026-04-20 08:00,2026-04-20 11:30,更换减速机润滑脂，检查背隙,正常,2026-08-18,合成
MT-CNC001-0702,EQ-CNC-001,主轴,点检,2026-07-02 14:00,2026-07-02 15:00,主轴温升和异响点检,发现异常已处理,2026-09-30,合成
```

| 列 | 说明 |
|---|---|
| `record_id` | `MT-{设备短码}-{MMDD}`，设备短码去掉 `EQ-` 和横线（`EQ-RB-022` → `RB022`）；同一天两条加 `-2` |
| `component` | 上表关键部件之一；整机保养写“整机” |
| `maint_type` | 计划保养 / 点检 / 润滑 / 换件 / 校准 |
| `end_time` | 保养结束时间，也是这条记录**开始能被查到**的时间 |
| `result` | 正常 / 发现异常已处理 / 发现异常待处理 |
| `next_planned_date` | 保养当时就排好的下次日期（agent 可以提前看到） |

**重要约定**：维保记录会直接影响 agent 的结论（比如“刚保养过，可能是磨合期误报”）。所以：

- **只有 1 条演示用例**有意把保养放在某个事件之前，放在哪由我挑好事件后告诉你；这条会写进 `data/README.md` 的“有意设置”一节；
- 其余记录按维保周期正常排，**不要贴着故障放**：官方故障维修单（`data/official/data/03_设备故障维修记录.csv`）里每次故障前 7 天内不放保养。

## 2. 备件 `data/synthetic/spare_parts.csv`

```csv
part_id,part_name,equipment_type,component,stock_qty,safety_stock,lead_time_days,unit_price,location,source,snapshot_at
SP-001,RV减速机总成,装配机器人,RV减速机,1,1,21,18500,备件库-A-03,合成
SP-002,主轴轴承组,五轴加工中心,主轴,0,2,14,6200,备件库-B-01,合成
```

- `equipment_type` 写上表的设备名称；`component` 写关键部件；
- 10 个关键部件每个至少对应 1 种备件；有意留 1–2 种库存低于安全库存，用来演示“缺货时提示采购周期”；
- `lead_time_days` 是采购周期（天），`unit_price` 单位为元。

## 3. 设备重要性 `data/synthetic/equipment_criticality.csv`

```csv
equipment_id,criticality,is_bottleneck,reason,source
EQ-RB-022,A,是,L06 唯一装配工位，停机直接停线,合成
EQ-AGV-031,C,否,有人工叉车可临时替代,合成
```

- `criticality`：A（停机直接停线）/ B（可短时降产）/ C（有替代）；8 台设备都要填；
- `is_bottleneck`：是 / 否。

## 4. 知识文档 `data/kb/docs/KB-{设备码}-{部件码}-{序号}.md`

约 12 篇：10 个关键部件各 1 篇，再加 1–2 篇讲误报和传感器问题（例如 `KB-GEN-SENSOR-01.md`）。设备码用 CNC / IM / RB / AGV / OVN。

```markdown
---
id: KB-RB-RV-01
title: 装配机器人 RV 减速机振动升高排查
equipment_type: 装配机器人
component: RV减速机
symptoms: [振动升高, 温度升高, 异响]
source: 自编（参考 GB/T xxxx 名称，不摘抄原文）
---
## 适用范围
## 典型征兆（在振动、温度、电流曲线上是什么样子）
## 可能原因（按常见程度排序）
## 排查步骤
## 处置措施和风险等级（低：加强监测、提前保养；高：停机检修）
## 所需备件（写备件表里的 part_id）
## 容易误判的情况（保养后磨合、传感器松动、环境温度变化等）
```

- 每节 2–5 句白话，全文 300–600 字，写给现场工程师看；
- 数字写成带单位的样子（如 `85℃`、`4.5 mm/s`）：agent 引用文档里的数字时，要连同单位一字不差地照抄，不带单位的数字它不能引用；
- 引用标准时只写名称和编号，不抄原文；
- 注意：本次数据里**转速、负载率、湿度是噪声**，文档里的判断依据请落在振动、温度、电流上。

## 5. 历史案例 `data/kb/cases/CASE-{四位序号}.md`

先写 3–5 条。`updated_at` 放在 2026-09 之前，这样调查 9 月的事件时都能查到。

```markdown
---
id: CASE-0001
equipment_type: 装配机器人
component: RV减速机
created_at: 2025-11-20 16:00
updated_at: 2025-12-05 10:00
verified: true
---
## 症状
## 当时的证据
## 根因
## 处置
## 结果（处理后信号是否恢复）
```

- `created_at`：案例建档时间；`updated_at`：这份内容（包括根因和 `verified`）写定的时间，不能早于 `created_at`。
- **每个文件是一份快照**：调查时点在 `updated_at` 之前，整条案例都看不到。不能拿后来才填的根因去回答更早的事件。
- 想表现“先建档、后来回填根因并审核”，就写两个文件，`id` 相同、`updated_at` 不同：`CASE-0001.md`（建档时，`verified: false`，根因写“待回填”）和 `CASE-0001-v2.md`（回填审核后，`verified: true`，写上根因）。调查时自动取调查时点之前最新的一份。
- `verified: true` 表示维修结果已回填并经过审核；没验证过的写 `false`：agent 可以提到“查到一条未验证的记录”，但不能用它肯定或排除根因。

## 6. 题集标注 `eval/pdm_golden.csv`（已生成，直接填）

`eval/pdm_golden.csv` 已经按事件表生成好：35 个事件各一行，`event_id`、`as_of`（默认调查时点）、`parts_basis` 和 `notes` 已填，你只需要填 `expected_status`、`expected_parts`、`must_cite`。`notes` 只写调查时点能看到的情况（类型、设备、信号、已告警几小时），没写之后有没有故障，请按当时能看到的信息判断。不必全标，先标 10 条左右（持续偏离、尖峰各几条）。用 Excel 打开不会乱码。

```csv
event_id,as_of,expected_status,expected_parts,parts_basis,must_cite,notes
EV-RB022-0915T10,2026-09-15 16:00,建议处置,RV减速机,专家判断,WO-2026-xxxx,振动和温度同时升高
```

| 列 | 说明 |
|---|---|
| `as_of` | 调查时点：站在这个时刻，只能看到这之前的数据 |
| `expected_status` | 疑似误报 / 需持续观察 / 需补充证据 / 建议处置 |
| `expected_parts` | 你认为最可能的部位，多个用“；”分隔 |
| `parts_basis` | 一律写“专家判断”：官方数据的故障原因是随机生成的，部位对不对没法用数据验证 |
| `must_cite` | 结论必须引用的出处 id，多个用“；”分隔 |
