# data

当前作品的主数据是官方素材包，放在 `data/official/`，不随仓库提交，放置方法见根目录 `README.md` 的“数据”一节。

## pdm/：公开数据（赛前下载，当前版本不使用）

Azure Predictive Maintenance（微软模拟数据，CC BY 4.0，来源见 `THIRD_PARTY.md`）的 1–100 号机器子集，由 `scripts/prepare_pdm_data.py` 生成，gzip CSV，pandas 可直接读：

| 文件 | 行数 | 内容 |
|---|---|---|
| `machines.csv.gz` | 100 | 机型（model1–4）、机龄 |
| `telemetry.csv.gz` | 876,100 | 2015 全年每小时电压、转速、压力、振动（每台 8761 条） |
| `errors.csv.gz` | 1,297 | 报错（error1–5） |
| `maint.csv.gz` | 3,299 | 保养换件记录（comp1–4，含 2014 下半年） |
| `failures.csv.gz` | 764 | 故障换件记录（comp1–4），可当标准答案 |

`raw/` 是下载的原始 CSV，不进仓库。

## 客诉数据（已归档，品质命题备选）

**全部是虚构的合成数据**：客户、零件、批次、检验结果、设备记录和历史案例都是编的，不来自任何真实公司。领域背景是“电子制造”（注塑电子外壳 + 显示模组），词表见 `docs/领域资料.md`。

| 文件 | 内容 | 工具 |
|---|---|---|
| `complaints.json` | 20 条原文：18 条客诉 + 2 条厂内异常（C012、C013） | `get_complaint` |
| `lots.json` | 11 个批次：零件、机台 / 产线、材料批次、包装、变更记录 | `get_lot` |
| `inspections.json` | 按批次的检验记录（来料、巡检、全检、出货、退回复检） | `get_inspections` |
| `process_records.json` | 按批次的工艺 / 设备记录（注塑参数、干燥、搬送振动） | `get_process_records` |
| `cases.json` | 10 条历史已闭环案例；`effective: null` 表示措施未验证 | `search_similar_cases` |

## 故意埋的考点

| 客诉 | 考什么 |
|---|---|
| C001 | 包装临时变更未评审 + 出货检验在包装前；工艺正常，要能排除 |
| C002 + C012 | 保压压力某时段偏低；10-01 修模是干扰项；厂内巡检已发现接近上限却放行 |
| C003 / C016 | 没有检验记录、工艺数据中断 → 证据不足；C016 是补充信息，用来演示“补证据后重新判断” |
| C004 | 证据链完整（材料让步接收 → 干燥不足 → 断口一致），可以提交审批 |
| C005 / C006 | 同样是划伤：C005 有设备振动异常，C006 在基线内，不能套用 C005 的原因；C005 还要区分客户声称 24 件和复检确认 15 件 |
| C007 | 疑似客户拆包划伤，不能直接判客户责任 |
| C008 / C009 | 批次不存在 / 批次号写错（字母 O 和数字 0） |
| C011 | 客户实测和我方复测冲突，疑似测量位置不同 |
| C014 | 色母变更未走变更管理 |
| C018 | 和 C002 同一批次但缺陷不同，不能混用原因 |
| C019 | 历史里没有亮点类案例 → 未找到相似案例 |
| C020 | 原文没有批次和缺陷信息 |

标准答案在 `eval/golden.json`（10 道题），工具读不到这个目录。
